# Security policy

Security fixes target the latest released version. During initial publication,
reports against the current `main` branch are also welcome. Older release lines
do not currently have a separate maintenance commitment.

## Report a vulnerability

On GitHub, use **Security → Advisories → Report a vulnerability** when private
vulnerability reporting is enabled. Include the affected version, reproduction
steps, impact, and a minimal example. Remove unrelated personal information.

Do not publish exploitable details, credentials, or raw diagnostic logs in a
public issue.

Reports are handled by the maintainer on a voluntary basis. There is currently
no response-time guarantee or paid bug bounty.
